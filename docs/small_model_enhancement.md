# EdgeMind 小模型能力增强调研

调研日期：2026-10-07。本文整理公开的工业项目、论文和官方实现，覆盖主要方法族及近期进展，不声称穷尽所有论文。文中的采用顺序和实验方案是针对 EdgeMind 的建议，尚未实现，也不表示用户已确认全部路线。

EdgeMind 的目标是从零训练模型，并通过可验证的设计提高小模型能力，再检查这些收益能否保留到端侧。v0.1 提供起点；后续成果应回答“改善了什么、为什么改善、付出了多少成本”。

## 先确认当前训练能力

- 现有代码支持 `batch_size=8`：一次读取 8 条，各条保持独立，按全部有效预测位置计算平均误差，再反向计算、更新一次参数。
- 现有代码没有跨批梯度累积：每批开始清空梯度，每批结束更新参数。没有 `accumulation_steps` 参数。
- “梯度”是误差对各参数的变化方向和敏感程度；“梯度累积”是连续几批保留这些信息，达到指定批数后才更新参数。它与一次放入 8 条数据是两个设置。
- 本地已用真实数据读取器、模型和训练循环，验证了 `(8, 512)`、`(8, 512)`、`(1, 512)` 三批的误差、反向计算、更新和保存。验证时缩小了模型宽度与层数，并用 CPU 替换 GPU 接口。
- 这证明批处理逻辑可用；正式约 0.277B 模型在 AutoDL 上使用批大小 8 的显存峰值与速度仍需实测。

当前主模型为 Dense Decoder-only，24 层、隐藏宽度 1024、6400 词元 BPE 词表。当前脚本按轮保存权重与配置，暂不支持中断恢复训练。本文没有修改训练代码。

## 怎样理解“小模型变强”

可以先问四个问题：模型是否学到了更有用的信息，训练目标是否奖励真正的任务成功，回答时是否给了适当的计算量，有限参数与设备内存是否用在了合适的地方。

还要分清三种收益：

| 收益 | 直白解释 | 应如何证明 |
| --- | --- | --- |
| 模型自身能力提高 | 在相同输入、工具和输出预算下，模型答对更多问题 | 固定独立测试集，对比训练方法或模型结构 |
| 整个系统完成任务的能力提高 | 模型学会查资料、调用计算器、根据工具结果继续行动 | 分别测模型决策、工具参数和最终任务成功率 |
| 端侧成本降低 | 同样任务占用更少内存，或在相同时间内完成更多工作 | 真机测内存、首字延迟、生成速度和持续运行表现 |

这三类都具有项目价值，但结果需要分别报告。模型权重、检索资料、额外模型和工具的成本都应计入对应实验。

## 工业项目中值得学习的经验

下表的项目事实来自作者公开资料；“对 EdgeMind 的意义”是本次调研后的判断。公开成绩通常对应特定测试设置，不能直接推断我们也能获得相同成绩。

| 项目 | 公开路线 | 对 EdgeMind 的意义 |
| --- | --- | --- |
| 面壁 MiniCPM / MiniCPM5 | 早期研究可迁移的训练设置与 WSD 学习率安排；2026 年 MiniCPM5 采用标准 Dense 模型，并结合示范微调、强化学习和 On-Policy Distillation | 重点学习数据与训练设计，再逐个验证增强方法。[MiniCPM 论文](https://arxiv.org/abs/2404.06395)、[官方项目](https://github.com/OpenBMB/MiniCPM) |
| Liquid AI LFM2.5-350M | 350M 模型面向工具调用、抽取与结构化输出；公布的预训练量为 28T 词元，并使用强化学习 | 与我们的参数规模很接近，可作为任务与设备效率的参考；训练量差距必须明确。[官方说明](https://www.liquid.ai/blog/lfm2-5-350m-no-size-left-behind) |
| Qwen3.5-0.8B | 混合 Gated DeltaNet 与注意力层；官方配置以三个前者配一个后者形成重复分组 | 证明混合结构已进入工业小模型；0.3B 上的收益仍需自己验证。[官方模型说明](https://huggingface.co/Qwen/Qwen3.5-0.8B) |
| Hugging Face SmolLM2 / SmolLM3 | 重视数据配比、分阶段训练、专门能力的追加训练和后训练；公开训练经验 | 学习如何做对照实验与追踪各阶段能力。其语料和语言覆盖需要按中文目标重新选择。[SmolLM2 论文](https://arxiv.org/abs/2502.02737)、[SmolLM3 说明](https://huggingface.co/blog/smollm3) |
| Microsoft Phi-1-small | 350M 模型使用教材式数据和代码练习 | 参考“把有限训练量用于容易学、能验证的内容”，不直接迁移其代码成绩到中文任务。[原论文](https://arxiv.org/abs/2306.11644) |

## 方法一：提高每份训练数据的价值

| 方法 | 为什么可能有效 | EdgeMind 的安排与证据 |
| --- | --- | --- |
| 清洗、去重、排除测试集泄漏 | 减少重复内容和噪声，把训练时间用于更多有效信息 | 优先采用。Hugging Face 的 DataTrove 提供过滤与去重组件；先做当前数据需要的一项处理即可。[官方实现](https://github.com/huggingface/datatrove) |
| 调整语料配比 | 日常中文、代码、数学的比例会改变模型学习的重点 | 先固定一份基线，再一次改变一个比例；比较相同有效训练词元数。[SmolLM2](https://arxiv.org/abs/2502.02737) |
| 教材式合成数据 | 定义、例子、练习把知识表达得更清楚，降低模型从杂乱文本中归纳规律的难度 | 高优先级候选。先做一种可验证的中文任务，再扩展；需要检查生成内容是否正确。[Phi 论文](https://arxiv.org/abs/2306.11644) |
| 简化任务分布、控制难度 | 先让模型在明确任务范围内建立稳定规律，再逐步增加变化 | 可用，但保留未见模板与更难样例。TinyStories 支持受控数据的思路，其英文故事结论不等于通用能力。[TinyStories](https://arxiv.org/abs/2305.07759) |
| 持续预训练、分阶段追加训练 | 已有语言基础后，追加目标领域文本，补足领域知识与常用表达 | 在首轮 Base 后考虑，混入一般文本并监测原有能力是否下降。[SmolLM3](https://huggingface.co/blog/smollm3) |
| 更多有效训练词元 | 小模型的能力还取决于学过多少有效信息，不只取决于参数量 | 预算内逐段增加，记录新增成本与收益；重复同一批数据不等价于获得同量新信息。[SmolLM2](https://arxiv.org/abs/2502.02737) |

DataTrove 是处理数据的工具，不会自动决定 EdgeMind 最佳语料配比。当前 MiniMind 语料可以保留为 v0.1 的训练基线；后续候选包括 [FineWeb2](https://huggingface.co/datasets/HuggingFaceFW/fineweb-2)，应先检查目标语言的一个小子集。

## 方法二：让大模型提供更合适的教学信息

“知识蒸馏”是让较强的教师模型提供训练信号，帮助小模型学习。EdgeMind 的 Base 权重仍从随机初始化开始；教师可以在后续阶段提供示范。

| 方法 | 直白解释 | EdgeMind 的安排与证据 |
| --- | --- | --- |
| 答案示范蒸馏 | 老师给出正确答案，小模型练习生成它 | 最容易开始。先固定任务、统一输出协议、检查答案，再训练。[DeepSeek-R1](https://arxiv.org/abs/2501.12948) |
| 推理过程蒸馏 | 示范不只含答案，还解释如何得到答案 | 高优先级。对照“只有答案”和“简短有效步骤”；原论文的模型与任务设置不同，EdgeMind 的方案属于借鉴。[Distilling Step-by-Step](https://aclanthology.org/2023.findings-acl.507/) |
| 根据学生自己的输出提供指导 | 学生先回答，老师针对它实际会犯的错误给反馈 | 很适合形成项目实验。工业完整版本可利用逐词元概率，工程成本较高。[MiniCPM5 的训练路线](https://github.com/OpenBMB/MiniCPM#training-recipe)、[Google SKD](https://research.google/pubs/speculative-knowledge-distillation-bridging-the-teacher-student-gap-through-interleaved-sampling/) |
| 概率分布蒸馏 | 学生学习老师对不同候选词元的评分，而不只模仿一个答案 | 后续考虑。需要教师模型的输出分数，以及词表和位置的对齐；不同分词器不能直接逐列比较。[MiniCPM5](https://github.com/OpenBMB/MiniCPM#training-recipe) |
| 中间表示或注意力蒸馏 | 学生模仿老师处理信息时的部分内部关系 | 研究候选。模型尺寸、层数、分词不同会增加对齐成本；MiniLM 的主要证据来自编码器。[MiniLM](https://arxiv.org/abs/2002.10957) |
| 多位任务教师 | 数学、工具、语言各有较强教师，再把示范汇入一个学生 | 有多个成熟任务后考虑；首轮用一个教师更容易归因。[MiniCPM5](https://github.com/OpenBMB/MiniCPM#training-recipe) |

现有 6400 词元词表与外部教师的词表通常不同，因此首个蒸馏实验建议采用文字示范。让教师纠正学生回答、随后用正确文本微调，可称为“错误驱动的示范蒸馏”；完整复现逐词元 On-Policy Distillation 则还需要概率对齐和专门训练目标。

例如，题目是“三盒笔，每盒四支，送出两支，还剩多少”。可以分别训练“10”和“先算 3×4=12，再算 12−2=10”。比较同一批未见题目上的正确率、生成长度和时间，才能判断步骤对小模型是否有帮助。更长的解释是否更好，属于待检验问题。

## 方法三：改变后训练目标

| 方法 | 直白解释 | EdgeMind 的安排与证据 |
| --- | --- | --- |
| 示范微调，SFT | 给出问题与目标回答，让模型学会按要求回答 | 第一项后训练能力。需有可用 Base；高质量示范的价值可参考 LIMA，但其 65B 基础不能直接外推到 0.3B。[LIMA](https://arxiv.org/abs/2305.11206) |
| 偏好优化，以 DPO 为代表 | 同一个问题给出较好与较差回答，训练模型更倾向较好回答 | 有可靠答案对后考虑；“更好”应尽量由任务正确性定义。[DPO](https://arxiv.org/abs/2305.18290) |
| 可验证奖励的强化学习，RLVR | 模型尝试回答，程序检查是否答对，再根据检查结果调整模型 | 后续重点候选。数学、代码、工具执行可获得较可靠反馈。[2026 年小模型代码实验](https://arxiv.org/abs/2605.30478) |
| 分组比较的强化学习，以 GRPO 为代表 | 对同一道题生成多个答案，比较好坏，引导下一次生成 | 先有能偶尔成功的任务和可靠评分，再做小规模 SFT 对照；多次生成消耗预算。[DeepSeekMath](https://arxiv.org/abs/2402.03300) |
| 按推理步骤反馈 | 不只检查最终答案，还指出哪一步出错 | 可先用于筛选训练数据；单独训练步骤评分模型成本更高。[Let's Verify Step by Step](https://arxiv.org/abs/2305.20050) |
| 自生成、筛选、再训练 | 保留模型通过外部检查的回答，再用这些回答继续训练 | 在有一定正确率之后尝试。正确结论也可能配有错误过程，仍需校验。[STaR](https://arxiv.org/abs/2203.14465) |

2026 年的小模型代码研究指出，只惩罚格式或静态检查问题，可能让模型靠输出更短内容获得奖励，却没有真正提高功能正确率。EdgeMind 应把最终任务是否完成放在评分核心。[原论文](https://arxiv.org/abs/2605.30478)

另有 70M–500M 模型强化学习的近期研究报告了数值与奖励相关失效。这可以帮助设计诊断，但仍需独立复现，不能据此保证我们的训练稳定或有效。[2026 年研究](https://arxiv.org/abs/2607.25091)

LoRA 是冻结大部分原权重、训练少量附加参数的微调方式；QLoRA 进一步压缩冻结权重，主要降低微调内存需求。它们可以帮助节省实验成本，能力提升仍来自数据与训练目标。对当前 0.277B 学生，先评估全参数微调的实际成本，再决定是否需要它们。[LoRA](https://arxiv.org/abs/2106.09685)、[QLoRA](https://arxiv.org/abs/2305.14314)

## 方法四：在回答时合理多算一点

| 方法 | 直白解释 | EdgeMind 的安排与证据 |
| --- | --- | --- |
| 给示例、使用简短步骤 | 用清楚的任务示例或中间步骤帮助当前回答 | 便宜的对照项；0.3B 是否能利用这些信息需要实测。[步骤蒸馏研究](https://aclanthology.org/2023.findings-acl.507/) |
| 多个候选，再验证或投票 | 同一题尝试几次，选更可靠的结果 | 适合有程序检查器的任务；需要记录候选数量和全部生成成本。[推理时计算研究](https://arxiv.org/abs/2408.03314) |
| 根据外部反馈改错 | 工具指出参数或计算错误后，让模型再尝试一次 | 可用于工具任务；先限制重试次数并检查最终结果。[ReAct](https://arxiv.org/abs/2210.03629) |
| 按难度分配思考量 | 简单问题直接答，困难问题用更多步骤、候选或工具 | 有研究支持这一方向，EdgeMind 的判断规则与收益属于待验证设计。[推理时计算研究](https://arxiv.org/abs/2408.03314) |

同一模型多次尝试后的成绩，要与一次回答的成绩分别记录。用更多时间换取正确率，本身是重要设计，但端侧是否划算必须看总延迟。

## 方法五：教会模型查资料、使用工具和按协议输出

| 方法 | 直白解释 | EdgeMind 的安排与证据 |
| --- | --- | --- |
| 本地检索增强，RAG | 先找出相关资料，再让模型结合资料回答 | 适合设备知识问答；小模型仍需学会准确使用资料。检索索引的内存与时间要计入系统成本。[RAG](https://arxiv.org/abs/2005.11401) |
| 工具调用训练 | 学会选择计算器、查找工具等，并填写正确参数 | 高优先级。先限定 3–5 个本地工具，测工具选择、参数与最终完成率。[Toolformer](https://arxiv.org/abs/2302.04761) |
| 交替推理与行动 | 看工具结果，再决定下一步 | 单次工具调用稳定后再增加多步任务。[ReAct](https://arxiv.org/abs/2210.03629) |
| 受约束的生成格式 | 在生成时限制合法输出，例如要求满足 JSON 结构 | 可减少格式错误；语法合法仍需要检查参数含义。部署框架兼容后可利用现成能力。[llama.cpp 文档](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md) |
| 小模型与大模型分工 | 小模型处理简单请求，困难请求由更大模型接管 | 系统设计候选；应统计接管率和额外成本。调用云端大模型的结果需明确标为协作系统结果，而不是全离线小模型成绩。 |

一个具体验收例子是：用户要求计算笔的数量，模型选择计算器，正确传入表达式，读取计算结果，再给出答案。只生成合法 JSON，不能证明整个任务已经完成。

## 方法六：探索结构与训练目标

下列方向可以产生有价值的架构实验；通常涉及重新训练或专门适配训练，也要提前检查端侧推理是否能运行对应结构。

| 方向 | 它试图解决什么 | EdgeMind 的判断与证据 |
| --- | --- | --- |
| 深度、宽度和前馈层预算 | 在相同总参数预算内，研究层数与每层容量怎样分配 | 最容易开始的结构实验。一次只比较两种配置，核对实际总参数、训练量和时间；借鉴小模型的受控实验思路。[MiniCPM](https://arxiv.org/abs/2404.06395) |
| 分组或压缩注意力缓存 | 减少生成时保存的历史键值信息 | 当前已有 GQA；MLA 等压缩方式可作为后续研究，优先核对算子与部署成本。[DeepSeek-V2](https://arxiv.org/abs/2405.04434) |
| 稀疏注意力、局部窗口、位置编码改动 | 减少长文本处理成本，或改变长距离信息的表达 | 长上下文成为目标时再研究；当前长度 512 的收益不应预设。[MiniCPM4](https://arxiv.org/abs/2506.07900)、[SmolLM3](https://huggingface.co/blog/smollm3) |
| 共享层、循环使用同一组层 | 用较少独立权重完成更多次计算 | 值得独立实验。需匹配推理时间，不能只比较参数量；重复计算也要专门训练。[循环深度语言模型](https://arxiv.org/abs/2502.05171) |
| 短卷积与注意力混合 | 一部分层处理附近信息，一部分层保留远距离交互 | 很适合关注端侧的后续结构分支；先替换少量层，实测中文能力与设备时间。[LFM2 官方结构](https://www.liquid.ai/blog/liquid-foundation-models-v2-our-second-series-of-generative-ai-models) |
| 线性注意力与标准注意力混合 | 用紧凑状态处理较长历史，保留部分完整注意力 | 研究候选。可参考 Gated DeltaNet，核对长期信息保留和部署算子。[Qwen3.5 官方配置](https://huggingface.co/Qwen/Qwen3.5-0.8B) |
| 状态空间模型，SSM | 用逐步更新的状态概括历史，改善长序列成本 | 有较多研究，实际速度依赖实现和硬件；作为较后阶段分支。[Mamba](https://arxiv.org/abs/2312.00752)、[Mamba-2](https://arxiv.org/abs/2405.21060) |
| 混合专家，MoE | 准备多组参数，每个输入只选择部分参与计算 | 活跃参数少也可能需要存放大量总参数；在手机预算下优先级较低。[Switch Transformer](https://arxiv.org/abs/2101.03961) |
| 查表式条件记忆 | 为常见局部知识增加便于查询的存储，给神经网络留出其他计算空间 | 2026 年 Engram 值得跟踪，但额外记忆表必须计入参数和内存预算；0.3B 结果未验证。[Engram](https://arxiv.org/abs/2601.07372) |
| 同时预测多个未来词元，MTP | 每个位置除下一词元外，再学习后面几个位置 | 适合后续小型训练目标实验；增加的输出头与误差如何平衡需要验证，论文大模型收益不能直接外推。[MTP](https://arxiv.org/abs/2404.19737) |
| 在内部数值状态中思考 | 让模型在内部表示上继续计算，减少把所有中间步骤写成文字的需求 | Coconut 等有研究证据，但训练和生成路径需专门设计；可读短步骤方案稳定后再做。[Coconut](https://arxiv.org/abs/2412.06769) |
| 字节级模型和动态分块 | 直接处理字节，并按信息复杂程度决定分块 | 会改变分词、模型和训练链路，当前优先级低。[BLT](https://arxiv.org/abs/2412.09871) |
| 专门任务的递归小网络 | 在谜题等明确任务上，多次修正内部状态 | TRM 可启发专门任务分支，其成绩不能当作通用自回归语言模型证据。[TRM](https://arxiv.org/abs/2510.04871) |

循环深度语言模型的代表实验使用了 3.5B 参数与 800B 训练词元，因此是机制参考，不是本预算下效果的保证。TRM 的后续分析还指出任务标识与多次采样等因素影响成绩，复现时要单独控制这些因素。[循环模型论文](https://arxiv.org/abs/2502.05171)、[TRM 后续分析](https://arxiv.org/abs/2512.11847)

针对 EdgeMind 的架构探索，我建议优先顺序是：参数预算内的深宽对照，然后从“少量短卷积混合”与“共享层循环”中选一个；更大范围的线性注意力、条件记忆和字节模型放在已有实验结果之后。

## 方法七：让改善后的能力更好地保留到端侧

| 方法 | 直白解释 | EdgeMind 的安排与证据 |
| --- | --- | --- |
| 训练后低比特量化，PTQ | 用更少比特存储训练好的权重 | 先建立量化前后对照；具体格式按推理框架选择。[AWQ](https://arxiv.org/abs/2306.00978)、[GPTQ](https://arxiv.org/abs/2210.17323) |
| 量化感知训练，QAT | 微调时模拟低精度误差，让模型适应最终的表示方式 | 如果实际量化导致任务能力明显下降，再做一项针对性实验。[PyTorch 官方说明](https://pytorch.org/blog/quantization-aware-training/) |
| 结构化裁剪 | 删除部分模型维度，再检查损失并补充训练 | 较后阶段候选；已有小模型容量紧张，需要先找出可删部分。[SliceGPT](https://arxiv.org/abs/2401.15024) |
| 原生极低比特训练 | 训练时就约束权重表示，改变模型与计算方式 | 属于新训练分支，硬件实现也要匹配；当前优先级低。[BitNet b1.58](https://arxiv.org/abs/2402.17764) |
| 推测解码 | 小模型先给草稿，更大的目标模型验证，减少目标模型逐词计算次数 | 可研究推理加速；最终分布来自目标模型，需要计入目标模型成本。[原论文](https://arxiv.org/abs/2211.17192) |
| 合并同一基础模型的任务分支 | 将多个微调分支的权重变化组合到一份模型 | 有多个可靠分支后再试，检查能力是否互相干扰。[TIES-Merging](https://arxiv.org/abs/2306.01708) |

量化、缓存和推理实现可降低设备成本，从而给更长上下文或更多推理尝试留出预算。是否提高了同一模型的任务正确率，要另行测量。

## 方法八：让训练预算用得更有效

学习率安排、优化器设置、批大小、样本拼接与数值稳定性，会影响同样预算能得到什么模型。它们值得研究，但每次改动应由实际现象驱动。

MiniCPM 的 WSD 思路把训练分为预热、稳定训练与衰减；适合按预算持续追加训练的研究。当前 EdgeMind 使用固定学习率，WSD 属于后续独立实验建议，不是本次已经实现的功能。[MiniCPM](https://arxiv.org/abs/2404.06395)

样本拼接可减少短文本补齐造成的无效计算；实现时必须明确不同文档之间是否允许相互关注，并正确保留起止标记和训练目标。它主要提高预算使用效率，可参考公开训练经验。[SmolLM3](https://huggingface.co/blog/smollm3)

## 建议优先选择的三个能力实验

以下是实验提案，按顺序逐项开展，不同时搭建全部代码。

### 实验 A：经过校验的简短教师示范

研究问题：同样大小的模型，经过检查的简短示范，能否比普通示范微调得到更好的任务表现？

- 先选择一种任务，例如简单中文算术或单次本地工具调用。
- 建立普通 SFT 对照版本，再加入“教师示范＋程序校验”这一项变化。
- 如需比较解释长度，再单独增加“只有答案”和“短步骤”的对照。
- 尽量匹配训练问题、有效训练词元数和训练预算；解释长度不同导致的预算差异单独报告。
- 测未见题目的正确率、结构化参数正确率、输出长度和回答时间。

这一实验容易解释：教师提供教学信息，程序减少错误示范，学生用有限容量学习目标任务。老师写出的过程是否适合 0.3B，仍由实验决定。

### 实验 B：根据真实失败补数据

研究问题：相同新增训练预算，专门补学生容易犯错的类型，是否比再追加普通示范有效？

- 使用独立的开发集收集模型错误，按类型整理，例如单位遗漏、工具选错、参数抄错。
- 教师为这些错误类型生成新示范，程序校验答案，再作一次小规模微调。
- 保留一份等预算的普通新增数据对照。
- 最终测试集持续隔离；不能把最后验收题的错误直接变成训练数据。

这会形成“发现问题—设计数据—验证改进”的完整研究过程，也适合解释个人贡献。

### 实验 C：一个结构变化的受控对照

研究问题：在相近总参数和训练预算下，短卷积混合或共享层循环，能否改善能力与端侧成本的取舍？

- 保留当前 Dense 模型作为基线，只选择一种结构变化。
- 先用较小模型或较短训练预算确认基本行为，再决定是否投入正式训练。
- 结构变化通常需要重新训练或专门适配，不能把改过结构直接加载旧权重视为完整训练方案。
- 对比总参数、有效训练词元、训练时间、任务正确率，以及相同设备上的峰值内存和延迟。
- 共享层方案还要按相同推理时间或计算预算比较，明确重复次数。
- 正式投入前完成最小端侧兼容性验证；新算子能在 PyTorch 上运行，不代表手机推理框架已经支持。

## 怎样证明“逼近更大模型”

先把目标写成可以验证的描述，例如“在中文短指令与三个本地工具组成的独立测试集上，用固定输出预算，缩小与指定较大模型的任务成功率差距”。任务范围与验收标准仍需最终确定。

建议固定一份测试集，使用开发集做选择，测试集只用于最后验收。模板、数值、实体与场景应有未见变化，避免只学会背固定答案。

每项能力增强要先与普通 SFT 或现有同参数版本比较；再与明确版本的外部模型比较。各模型的工具、资料、上下文、输出预算与评分规则应一致。

至少保留以下记录：

| 记录项 | 作用 |
| --- | --- |
| 数据来源、处理规则、训练与测试的划分 | 能解释学到了什么，检查是否混入验收题 |
| 实际总参数与有效训练词元数 | 能比较规模与训练量，排除单纯多训的影响 |
| 实验唯一主要变化 | 能解释改善来自哪项设计 |
| 任务正确率和失败类型 | 能区分语言流畅、格式正确与实际完成任务 |
| 生成长度、时间和额外工具或模型调用 | 能解释更多计算是否值得 |
| 量化前后正确率、真机内存与速度 | 能证明增强收益是否保留到端侧 |

当前 `eval_pretrain.py` 的续写是直观检查。首轮训练之后，建议下一项小功能是固定独立测试集上的定量评测，再进入第一项能力增强实验。

具体实验成功率、所需训练量和架构收益目前都是待测事项。完整流程是基础，持续改进的实验与证据是 EdgeMind 的研究主线。
